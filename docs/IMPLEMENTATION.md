# Implementation and handover

## Implemented behavior

- Fixed SZ supply is minted once to the designated treasury. Online/offline packages are backed by SZ held in contract custody. Buyer matching reassigns existing units; remaining quantity comes from treasury inventory. No early claim, routine mint, burn, testing bypass, or package-owner reassignment exists.
- Each package has twenty 365-day tranches. The first nineteen use `amount / 20`; the last receives the exact remainder. Per-tranche filled quantities are immutable history. A min-heap indexes the next unconsumed tranche of every package, including future tranches. Partial fills persist and matching follows unlock timestamp, with package ID as the tie breaker.
- The initial $1 reference price compounds by 2.33% using both threshold counters. A purchase uses its preceding price, records actual payment value and updates counters afterward. Fixed-point exponentiation is logarithmic and bounded to 4096 steps to fail before arithmetic capacity is exceeded.
- Buyer quantity uses the reference price. Staker payout uses the lower of that price and 100× original price. Any cap spread and sub-unit rounding remainder goes to AW. Payouts floor to a micro-USDT; final sub-micro amounts may be zero. Quantity remains conserved. This explicit cap-spread convention is an implementation assumption requiring economic acceptance.
- Year-1 buybacks pay USDT.c; later years transfer the applicable collateral to AW and mint ET to the original owner. Mint failure reverts the entire transaction. ET minter is permanently bound once to SZ; no administrator can mint or rebind after initialization. Optional ET cap is constructor-configurable.
- Admin funds can be deposited, consumed by the same buyback engine without a new package, or returned to treasury. Each matching transaction is bounded to 200 fills; larger operations revert atomically and must use smaller purchases/budgets. Queue insertion/removal is logarithmic.
- The source adapter accepts exactly one immutable approved token, moves it directly to treasury, and emits a nonce-based deposit record. Source precision from 6–18 decimals is normalized exactly, without floating point. Transfer-tax tokens are rejected. There is no reverse bridge, redemption, burn/release or automatic refund.
- The coordinator validates source/destination chain identity, adapter/token/treasury configuration, successful canonical receipts and confirmation depth. It mints only through the dedicated relayer, records source and mint hashes, rejects observed reorganizations before mint, retries failures, and recovers completed mints on restart. Wrapper identities include source chain, adapter and nonce. Admin and bridge roles cannot overlap.
- The database accepts verified events only. Browser-supplied “confirmed purchase” and offline-sale POSTs now return 410. SQLite persistence and unique event/deposit identities prevent duplicate records. Public history/reconciliation data contains already-public chain information; no write API or login secret is exposed.
- The UI shows actual chain balances, partial-fill schedules, prices, custody, treasury records, ET receipts and confirmed events. Purchases enforce a user-controlled minimum quantity and deadline. Admin actions await successful transaction receipts. Source deposit, history, reconciliation, pause, role management, package lookup and historical import forms are connected to real APIs/contracts.

## Assumptions from the supplied v1.1 recommendations

No direct SZ withdrawal; 1 dollar of substituted payout = 1 ET; uncapped ET by default; admin-funded buybacks enabled; genuine historical dates allowed and future dates rejected; zero wrapper fee. Default UAT purchase range is $1–$100,000, active-package count unlimited. These are editable deployment/admin parameters where applicable, not claimed client approvals. Minimum contract package quantity is 20 SZ base units, ensuring every annual tranche has a nonzero quantity. SZ is named Swiz with symbol SZ pending final identity confirmation.

## Deployment sequence

1. Complete the client inputs: fixed SZ total supply, final identity/cap, admin/multisig, treasury, dedicated relayer, production network and source treasury/token addresses. Supply and amounts use six-decimal **integer base units**. Do not copy example placeholders into a live environment.
2. Configure smartContract `.env` from its example. Missing/malformed deployment keys no longer fall back to a public development key. `npx hardhat run scripts/deployDestination.ts --network baseSepolia` deploys wrapper → SZ/ET wiring. ET is temporarily owned by the deployer only for binding; `bindMinter` permanently renounces ownership. SZ and wrapper admin roles are assigned directly to the company address, so the deployer receives no continuing protocol role. Save all emitted addresses and deployment block.
3. Deploy `SourceDepositAdapter` on each selected compatible source testnet with `scripts/deploySource.ts` and its approved mock/test token. Mainnet token contracts and final confirmation policies require independent verification before production. Set BSC_TESTNET_RPC_URL for the bscTestnet network; a future destination can use PRODUCTION_RPC_URL.
4. Populate `config/deployment.example.json` with the actual addresses, start blocks and reviewed confirmation counts. Starting at the deployment block avoids replaying unrelated chain history. Set `DEPLOYMENT_CONFIG`, then run `scripts/configureSources.ts` on the destination with the company admin signer. A multisig must execute equivalent `configureSource(chainId, adapter)` calls. Source addresses are immutable once allowlisted; changes require a new wrapper deployment.
5. Verify SZ/ET/USDT.c decimals, total supply, SZ collateral address, ET minter, admin/relayer separation and treasury addresses on chain. Check both ADMIN_ROLE and DEFAULT_ADMIN_ROLE when transferring/recovering administration. Do not revoke the last administrator before replacement access is verified.
6. Set backend environment, use a persistent SQLite volume and **one coordinator process/replica per relayer/database**. Keep relayer keys on the backend host only. Run `npm start`. Back up the database and monitor `/api/v1/health`; inspect reconciliation for RETRY/REJECTED/SUBMITTED states. Pending destination transactions require receipt resolution; replacements/cancellations and catastrophic post-confirmation reorganizations need operator reconciliation. Do not manually fabricate a mint for a missing deposit.
7. Set frontend deployed addresses, chain/RPC/explorer, Reown project ID and backend URL. `npm run build`; host the static output with SPA routing and HTTPS. No real credentials or deployment addresses are checked in. WalletConnect and Coinbase connector availability depend on the configured Reown project and wallet environment.
8. Run full UAT on Base Sepolia and all three selected source testnets. Local acceptance does not certify live RPC finality, wallet-provider behavior or deployed bytecode. Configure production token registry/confirmations and verify contracts before production activation.

## Historical migration

Use `importHistoricalSale(sale, filled[20], priorET, priorUSDT)` before closing migration. `sale` contains buyer, amount, value, price, purchasedAt, startedAt, referenceId. Integers are base units or Unix seconds; referenceId is the keccak256 hash of a unique offline payment reference. The filled array contains **SZ quantities already bought back**, not boolean flags. Only the remaining SZ is moved into custody; old ET is recorded, never minted again. Original value counts toward pricing. Reconcile source records and held tokens before import. Under the retained-custody model, timestamp determines unlocked eligibility; prior direct withdrawals require a separately reviewed migration mapping. `closeMigration()` permanently disables further historical state imports. Normal dated offline sales remain available.

## Validation and outstanding external inputs

18 contract tests cover custody/supply, price updates, dates/rounding, partial fills, FIFO, Year-1/Year-2 payouts, cap/atomic failure, migration, admin funding, pause and source identity. Six backend tests cover forged POST rejection, exact decimal conversion, persistent identity, retries, reorg rejection and restart recovery. `scripts/e2e-local.mjs` validates source treasury deposit → confirmation verification → destination mint → restart idempotency → purchase custody → indexed history against a local JSON-RPC chain. Frontend TypeScript/build and browser page/access/mobile checks pass.

Remaining external acceptance work: final supply/economic choices, real wallet/project credentials, approved production token addresses/confirmations, actual Base Sepolia multi-wallet and three-source UAT, deployed verification, production network/hosting, branding/support details and legal documents. No live network deployment or production transaction was performed.

An obsolete minting script contained a hardcoded private key. The active script was removed. Treat any wallet using that key as exposed and rotate it before further use; historical archives/backups may still contain it. Legacy JSON records are retained as evidence only and are not promoted to confirmed chain history.
